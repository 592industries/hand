# H.A.N.D data inventory

Updated: October 11, 2026

This inventory describes the v2.2.1 implementation. It separates data stored by H.A.N.D from data that DeepSpace, Cloudflare, network providers, or the AI provider may process independently. Provider behavior is not treated as verified application behavior.

Confidence labels:

- **Verified** — directly supported by repository code or configuration.
- **Partially verified** — the application path is known, but provider behavior or production configuration is not fully visible in this repository.
- **Unknown** — no reliable evidence was available.

## H.A.N.D session lifecycle

1. The worker creates a cryptographically random session identifier and a secure, host-only cookie.
2. The identifier selects one isolated session room. It is not exposed in analysis URLs.
3. Valid session requests and an active WebSocket refresh `lastSeen`.
4. A closed or failed final connection schedules an alarm for 30 minutes after the latest activity.
5. If the room is active again when the alarm runs, cleanup is rescheduled. Otherwise serialized cleanup invalidates in-flight writes and `deleteAll()` removes only that room's application data.
6. Settings can send `DELETE /api/session` to perform the same isolated cleanup directly. Partial upload writes are removed per analysis if storage fails.

This is an inactivity-based cleanup design, not a guarantee that every copy held by infrastructure or an AI provider is erased within 30 minutes. Expiration is not independently rejected on every request. A restored browser session or later valid activity can refresh the timer before cleanup occurs.

## AI provider boundary

The application requests the Anthropic model configured in `src/ai/analysis.ts` through DeepSpace's server-side `createDeepSpaceAI` integration. The repository does not contain a direct Anthropic API key and does not establish a zero-data-retention agreement.

Anthropic currently states that commercial API inputs and outputs are not used for model training by default and that standard API content is normally deleted within 30 days, subject to agreement, legal, and misuse-prevention exceptions. These are provider statements, not application guarantees:

- <https://privacy.anthropic.com/en/articles/7996868-is-my-data-used-for-model-training>
- <https://privacy.anthropic.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data>
- <https://deep.space/privacy>

The production terms between DeepSpace and its model providers were not available in this repository. Provider-side prompt logging, proxy retention, and account-level opt-ins remain **unverified**.

## Data not intentionally requested

H.A.N.D does not provide fields for a name, email address, phone number, mailing address, billing information, account profile, precise location, or advertising identifier. It does not include a first-party account system, analytics SDK, or advertising SDK.

This does not mean such information cannot be processed. A user may place personal information in a note image, title, reference, or transcription, and hosting infrastructure may process network identifiers.

## Environment and bindings

The committed code uses platform bindings for the DeepSpace application, records, session room, AI proxy, assets, migrations, and environment selection. GitHub deployment authentication uses the repository secret `DEEPSPACE_SESSION`. Secret values are not part of this inventory and must not be committed. See `ENVIRONMENT.md`, `wrangler.toml`, `worker.ts`, and `.github/workflows/deploy.yml`.
